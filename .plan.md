# Implementation Plan

## Overview of Changes

8 feature groups across backend (TypeScript) and frontend (index.html).

---

## 1. Card Flip Animation
**File:** `public/index.html`

- Replace the existing `cardDeal` animation for community cards with a true flip: card starts face-down (rotateY 90deg), pauses, then flips to face-up.
- Flop cards stagger: 0ms, 120ms, 240ms delay per card.
- Turn and river: single card flip.
- Hole cards keep the existing `cardDeal` animation (slide in, no flip needed).

---

## 2. Preflop All-In Street Delays
**File:** `public/index.html`

- Add a client-side event queue. Instead of processing `hand:community_dealt` immediately, push it onto a queue.
- If the previous event was also `community_dealt` with no `action_required` in between (runout), delay processing by 500ms.
- This gives the "flop… pause… turn… pause… river" feeling during all-in runouts.

---

## 3. Per-Player Visible Timer
**Files:** `public/index.html`

- The server already sends `deadlineMs` on `hand:action_required`.
- Add a `seat-timer` element inside each seat that shows a live countdown (seconds remaining) only while that seat is the current actor.
- Separate from the existing action-bar timer bar (which stays for the local player).
- Timer disappears when the player acts or the street changes.

---

## 4. Ledger
**File:** `public/index.html`

- Track client-side: on `lobby:join_table` confirmation, record initial buy-in per player.
- On each `hand:complete`, compare `finalSeats` stacks against the recorded starting stacks to accumulate net profit/loss.
- Add a "Ledger" button in the table header (visible to all players).
- Opens a panel/modal listing each player: name | buy-ins | total in | current stack | net.

---

## 5. Card Reveal Button (Post-Action)
**Files:** `src/realtime/TableNamespace.ts`, `src/realtime/events/client-events.ts`, `src/realtime/events/server-events.ts`, `public/index.html`

- After a hand ends (either by showdown or all-fold), show a "Show Hand" button for the local player in the action bar.
- Client emits `hand:reveal_cards` with `{ handId }`.
- Server broadcasts `hand:cards_revealed` with `{ seatIndex, playerId, holeCards }` to the whole table.
- Other clients display those cards at the seat.
- Button disappears at the start of the next hand.

---

## 6. Host Player
**Files:** `src/types/index.ts`, `src/services/TableService.ts`, `src/realtime/LobbyNamespace.ts`, `src/realtime/TableNamespace.ts`, `public/index.html`

- Add `hostPlayerId: string` to `TableState`.
- `TableService.createTable()` takes `creatorPlayerId` and stores it.
- `LobbyNamespace` passes `creatorPlayerId` (the socket's userId) when calling `createTable()`.
- `table:state` event includes `hostPlayerId` so the client knows who the host is.
- Frontend stores `S.isHost = (socket.id === hostPlayerId)` and shows host-only controls.

---

## 7. Game Options Panel (Host Only)
**Files:** `src/types/index.ts`, `src/services/TableService.ts`, `src/services/GameService.ts`, `src/realtime/TableNamespace.ts`, `src/realtime/events/client-events.ts`, `src/realtime/events/server-events.ts`, `public/index.html`

### Settings stored in `TableState.settings`:
```ts
interface TableSettings {
  autoDeal: boolean;
  autoDealDelaySeconds: 2 | 4 | 6;
  runItTwice: boolean;
  rabbitHunting: boolean;
  showdownReveal: 'standard' | 'always' | 'never';
  actionTimeoutSeconds: number;
}
```

### Backend per-setting:

**a. Auto-deal**
- After `hand:complete`, `GameService` checks `settings.autoDeal`. If true, schedules `startHand()` after `autoDealDelaySeconds * 1000` ms.

**b. Run it twice**
- In `HandStateMachine`, when all players are all-in mid-hand with >1 street remaining, deal the remainder of the board *twice* and split each runout's pot between winners.
- Add `runItTwice` to the machine config so the FSM handles it automatically.

**c. Rabbit hunting**
- After a hand ends by everyone folding (not showdown), preserve the remaining `Deck` state.
- Add new FSM event `hand:rabbit` carrying the next N unrevealed cards.
- If `rabbitHunting` is enabled in settings, the server auto-sends this event after the fold win.

**d. Showdown reveal rules**
- `'always'` → current behavior (everyone shows).
- `'never'` → no hole cards revealed, only winner amount shown.
- `'standard'` → last aggressor shows first; called players must show to win; others can muck (mucking is client-side, server sends all cards but client hides mucked ones based on signal).

**e. Time bank**
- `settings.actionTimeoutSeconds` replaces `TableConfig.actionTimeoutSeconds` as the live value used by `GameService`.

**f. Player chip management**
- New socket event `table:adjust_chips` `{ targetPlayerId, amount }` (host only).
- `TableService.adjustChips()` directly modifies the seat's stack.
- Broadcasts `table:chips_adjusted` to the room.

**g. Game mode change**
- New socket event `table:change_variant` `{ variant }` (host only, between hands only).
- `TableService.changeVariant()` updates `config.variant`.
- Broadcasts `table:state` so all clients update their UI.

### Frontend (Game Options Modal):
- "⚙ Options" button in table header, visible to all but only interactive for the host.
- Modal with sections:
  - **Dealing:** Auto-deal toggle + delay selector (2s / 4s / 6s)
  - **Hand Rules:** Run it twice toggle, Rabbit hunting toggle, Showdown reveal radio (Standard / Always / Never)
  - **Time Bank:** numeric input for seconds
  - **Players:** list of seated players, each with + / − chips buttons (host only)
  - **Game Mode:** dropdown (NLH / PLO4 / PLO5 / PLO6), "Change" button (host only, disabled mid-hand)
- Non-host players see all settings as read-only.
